# Client Communications

## Overview
Client emails carry more weight than internal ones — every message represents your reliability. The bar is higher: clearer structure, tighter deadlines, and zero ambiguity. This skill covers professional tone, follow-up etiquette, and handling sensitive situations.

## When to Use
- Emailing a client, vendor, or external partner
- Sending proposals, quotes, or invoices
- Status updates and progress reports
- Follow-ups on pending decisions or payments
- Handling complaints or scope changes

**Do NOT use** for internal team communication, academic emails, or job applications.

## Core Principles

1. **Clarity over friendliness** — Client emails are decisions, not conversations. State the decision or action clearly first.
2. **Deadlines in subject or first sentence** — If something is due, say it immediately.
3. **One email, one ask** — Multiple asks per email = none gets answered. Split if needed.
4. **CC the right people** — Minimum necessary. No surprise CCs (never CC someone's boss as pressure).

## Structure

### Status Update
```
Subject: [Project] Status Update — [Date/Period]

Hi [Name],

Quick update on [project/area]:

• What's done: [completed items]
• What's in progress: [in progress with ETA]
• Blockers / needs decision: [list + who decides]
• Next step: [what happens next + when]

No action needed from you this week unless noted above.

Thanks,
[Your Name]
```

### Follow-up (Payment / Decision / Reply)
Use this when a previous email got no response after 3–5 business days.

```
Subject: Follow-up: [Original Subject]

Hi [Name],

Quick follow-up on my email from [date] about [topic].

I'd appreciate an update by [day] so we can keep things on track.
Let me know if you need anything else from my side.

Thanks,
[Your Name]
```

Always include the original context. Never just say "following up on my last email" — the client may not remember.

For escalated follow-ups where a deadline has been repeatedly ignored, the **tone_guide** assertive profile provides stronger language — but use it as a last resort, not a first response.

### Scope Change / Additional Request
```
Subject: Scope Update: [Project] — [Description of change]

Hi [Name],

You recently requested [specific change/addition]. This is outside the original scope agreed on [date].

Impact:
• Timeline: [+X days]
• Cost: [+$Y / +Z hours]

Please confirm you'd like to proceed so I can update the schedule.

Thanks,
[Your Name]
```

Always quantify the impact. "This will take more time" is not enough — give a number.

### Complaint / Issue Handling
```
Subject: Issue: [Brief description] — [Project]

Hi [Name],

I understand the issue with [specific problem] and apologise for the inconvenience.

Root cause: [what happened — factual only]
Fix: [what we're doing about it]
ETA: [when it will be resolved]
Prevention: [how we'll avoid recurrence]

I'll follow up once the fix is in place. Let me know if you need anything else.

Thanks,
[Your Name]
```

Lead with the apology, then facts, then fix. Never explain the root cause before apologising — it reads as defensive.

## Tone Table

| Situation | Tone | Greeting | Key phrases |
|-----------|------|----------|-------------|
| Routine update | Casual professional | `Hi [Name],` | `Quick update`, `No action needed` |
| Follow-up | Polite + direct | `Hi [Name],` | `I'd appreciate an update by...` |
| Payment reminder | Firm + professional | `Dear [Name],` | `Per our agreement dated...`, `Please remit by...` |
| Complaint | Empathetic + factual | `Dear [Name],` | `I understand...`, `Apologies for...` |
| Proposal | Confident + warm | `Hi [Name],` | `I believe this addresses...` |

## Follow-up Schedule

| Scenario | First send | First follow-up | Second follow-up |
|----------|-----------|----------------|------------------|
| Proposal / quote | Day 0 | Day 3 | Day 7 (different person) |
| Payment due | Day of due date | Day 5 overdue | Day 10 (formal notice) |
| Pending decision | Day 0 | Day 5 | Day 10 (escalate if critical) |
| Meeting request | Day 0 | Day 3 | Day 7 (propose alternative) |

**Rule of thumb:** 3 attempts max per topic. After that, switch channel (call) or escalate.

## Red Flags

- About to CC someone's boss to pressure them → stop. Call the person first.
- Writing "As per my previous email" → stops the conversation. Rewrite as a summary.
- Explaining a problem before apologising → apologise first.
- Multiple asks in one email → pick the most important one. Split the rest.
- No deadline stated → the client won't know when to act. Add one.

## Common Mistakes

| Mistake | Fix |
|---------|------|
| No deadline in follow-ups | Always state when you need a response |
| CC as pressure tactic | Call the person instead — never CC over someone's head |
| "Per my last email" tone | Summarise the previous ask instead |
| Multiple CTAs in one email | One ask per email. Split if needed. |
| Emotional language | Stay factual. Write the email, wait 10 min, re-read. |
| Vague scope changes | Quantify timeline and cost impact |
