# Reply Etiquette

## Overview
How you reply signals how much you respect the reader's time and attention. Good etiquette means quoting strategically, setting the right recipients, and matching response tempo to expectations. This skill covers thread quoting, Cc/Bcc conventions, and response time norms.

## When to Use
- Replying to any email in an existing thread
- Forwarding a message to someone
- Deciding who to Cc or Bcc
- User asks "should I reply all?"
- User is unsure how much of the prior thread to include

**Do NOT use** when composing a fresh email to a new recipient — use email_structure instead.

## Core Patterns

### 1. Thread Quoting

**Rule:** Quote only what the reader needs to understand your reply. Never quote the entire thread verbatim.

| Situation | What to quote |
|-----------|---------------|
| Single question → reply | The question only (trim the rest) |
| Long thread → new participant | Summary of relevant decisions + your reply |
| Forward to someone else | Context line: what this is about + why they're getting it |
| Reply all | Same as single reply — don't inflate quoting for extra recipients |

**Format:**
```
> [Their question/point]

My reply here.
```

If the thread is longer than 5 messages, include a one-line summary before any quoted text:
```
[Summary: John asked about budget approval; Alice raised concerns about scope.]

> John: Can we get approval by Friday?

Already escalated to Nam. Awaiting his response.
```

### 2. Cc / Bcc Conventions

| Action | Rule |
|--------|------|
| **To** | People who must act or respond |
| **Cc** | People who need to know but don't need to act |
| **Bcc** | People who need visibility but their presence should be invisible to others |

**Cc guidelines:**
- Cc the minimum number of people — each additional Cc is noise
- Never Cc someone's boss to pressure them (passive-aggressive)
- If someone is added mid-thread, summarise the context for them

**Bcc guidelines:**
- Use for: manager visibility, compliance records, introducing a replacement
- Never Bcc to conceal a conversation that should be transparent
- Recipients in Bcc are not visible to each other or To/Cc — factor this into your quoting

**Reply vs Reply All:**
- **Reply** — only the sender sees it. Default.
- **Reply All** — only when every recipient needs your response
- If you are one of many recipients and your reply only matters to the sender, use Reply (not Reply All)

### 3. Response Time Norms

| Relationship | Expected window | If delayed |
|-------------|----------------|------------|
| Boss / client (urgent) | Within 4 business hours | Short apology + ETA |
| Colleague / peer | Within 24 business hours | No apology needed |
| Professor / academic | Within 48 hours | Brief acknowledgement |
| Cold / first contact | Within 24 hours | — |
| Newsletter / group | 1 week or never | — |

**If you cannot respond fully:** send a brief acknowledgement with an ETA:
> Got it, thanks. I'll have a full response by Thursday.

**Never:**
- Reply "just to acknowledge" without a timeline — leaves the sender hanging
- Let a direct question sit unanswered for more than 3 days

### 4. Forwarding Etiquette

When forwarding a message:
1. **Add context above the forwarded content** — explain what it is and why the recipient needs it
2. **Trim the forwarded thread** to the relevant parts
3. **Call out any action items** explicitly

```
Forwarding for your review. I need feedback on the budget line items (highlighted) by Friday.

─── Forwarded message ───
Subject: Q3 Budget Proposal
...
```

## Quick Reference

| Situation | Do | Don't |
|-----------|----|-------|
| Replying to specific question | Quote only that part | Quote entire thread |
| Adding someone mid-thread | Summarise context for them | Make them read 20 messages |
| Reply vs Reply All | Reply (single), Reply All (need all) | Default Reply All |
| Delayed response | Send acknowledgment + ETA | Stay silent |
| Forwarding | Add your context above | Forward raw without explanation |

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| Replying All when only sender needs response | Use Reply. Default to Reply. |
| Forwarding without context | Always write a line explaining why |
| Adding Cc to pressure someone | Never — passive-aggressive and corrosive |
| Quoting entire thread | Trim to relevant question(s) only |
| Letting questions sit >3 days | Send an acknowledgement with ETA |
