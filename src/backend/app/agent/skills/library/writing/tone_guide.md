# Tone Guide

## Overview
The same message lands differently depending on tone. Picking the wrong tone damages rapport — sounding too casual with a professor or too stiff with a teammate. This guide maps recipient relationship → appropriate tone → concrete language markers.

## When to Use
- Composing any email where the recipient relationship is known
- User says "reply to this" without specifying tone
- User asks "is this too casual/formal?"
- Replying to a cold email or first contact

**Do NOT use** when the user explicitly specifies a tone — follow their instruction.

## Tone Profiles

### Formal
**When:** Professor, client, boss, first contact, authority figure, any external stakeholder.

| Element | Guideline |
|---------|-----------|
| Greeting | `Dear Professor/Họ + chức danh,` or `Dear Mr./Ms. LastName,` |
| Body | Complete sentences. No contractions. Passive voice acceptable for deference. |
| Requests | `I would appreciate it if...`, `Could you please...` |
| Closing | `Best regards,` / `Sincerely,` / `Trân trọng,` |
| Emoji | Never |
| Exclamation marks | Rare, and only for genuine enthusiasm |

### Casual (Professional)
**When:** Colleague at same level, teammate, regular collaborator, internal peer.

| Element | Guideline |
|---------|-----------|
| Greeting | `Hi Name,` or `Hey Name,` |
| Body | Mix of full sentences and bullet points. Contractions OK. |
| Requests | `Can you...?`, `Could you...?` |
| Closing | `Thanks,` / `Cheers,` / `Best,` |
| Emoji | One per email max, and only for warmth (😊 👍) — never in a complaint |
| Exclamation marks | Occasional, for enthusiasm |

### Assertive (Urgent / Follow-up)
**When:** Deadline has passed, previous email was ignored, need a decision fast.

| Element | Guideline |
|---------|-----------|
| Greeting | Same as baseline tone (don't change greeting to signal frustration) |
| Body | Shorter sentences. Action-oriented. State deadline explicitly. |
| Requests | `Please confirm by EOD.` / `I need your decision by Friday.` |
| Closing | `Thanks,` — no change |
| ⚠ Use sparingly | Overuse erodes relationships. Reserve for genuine urgency. |

> **⚠ Client context:** When the recipient is a client or external partner, assertive tone can damage the relationship. In client follow-ups, prefer **client_comms**'s approach: acknowledge the previous email, restate the ask, and set a polite deadline. Use full assertiveness only if the client has explicitly ignored multiple prior attempts.

### Empathetic
**When:** Delivering bad news, responding to a mistake, consoling, apologising.

| Element | Guideline |
|---------|-----------|
| Acknowledge first | `I understand this is frustrating.` before giving facts |
| Own the issue | `I'm sorry this happened.` / `That's on us.` |
| Solution next | `Here's what we're doing to fix it:` |
| Closing | Warm but professional: `Thanks for your patience,` / `I appreciate your understanding,` |

## Quick Reference

| Context | Tone | Greeting | Closing |
|---------|------|----------|---------|
| Professor / client | Formal | `Dear Dr. ...` | `Best regards,` |
| Teammate | Casual | `Hi ...` | `Thanks,` |
| Late follow-up | Assertive | *same as baseline* | `Thanks,` |
| Apology | Empathetic | `Dear ...` | `I appreciate your patience,` |

## Common Mistakes

| Mistake | Fix |
|---------|-----|
| Formal tone with peers | Reads cold and distant — match their tone |
| Casual tone with superiors | Reads disrespectful — err on formal side |
| Assertive tone for routine requests | Reads demanding — save for genuine urgency |
| Empathetic tone without solution | Reads hollow — always pair sympathy with action |
| Switching tone mid-email | Pick one tone and stay consistent |
